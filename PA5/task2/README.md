# Advanced Topics in Machine Learning - Assignment 5: Task 2 (LLM Alignment)

This repository contains the complete implementation and scientific analysis for Task 2 of the assignment, focusing on LLM Alignment. The objective is to align a `SmolLM2-135M` model using three distinct methods—DPO, PPO, and GRPO—and rigorously evaluate their behavioral trade-offs, including stability, verbosity bias, and reward hacking.

## Project Structure and File Guide

The project is organized into environment setup, training scripts for each algorithm, and a comprehensive evaluation pipeline. Here is a guide to what each file does and which stage of the pipeline it corresponds to.

### 1. Environment & Utilities

Due to library version conflicts between stable PPO implementations and newer GRPO implementations, this project requires specific environment configurations.

-   `check_env.py`: A utility script to verify that the installed versions of `trl`, `transformers`, and `peft` are compatible with the specific training script being run.
-   `requirements.txt`: Lists the dependencies for the main environment used for DPO and PPO.

---

### 2. Phase 1: Training the Models

These are the main executable scripts used to train the Reward Model and align the Policy Models.

-   `task2_reward_model.py`: Trains the **Reward Model (Judge)** on the ORCA DPO pairs dataset. This model serves as the ground-truth evaluator for PPO and GRPO.
-   `task2_dpo.py`: Aligns the base model using **Direct Preference Optimization (DPO)**. This serves as the stable, reference-free baseline.
-   `task2_ppo.py`: Aligns the model using **Proximal Policy Optimization (PPO)** with a sparse reward setup. It implements a manual training loop to ensure precise control over generation steps.
-   `task2_ppo_dense.py`: A modification of the PPO script that implements a **Dense (Token-level) Reward** signal. This is used specifically to investigate the emergence of verbosity bias.
-   `PA5_GRPO/task2_grpo.py`: Aligns the model using **Group Relative Policy Optimization (GRPO)**. *Note: This script resides in a sub-directory and requires a separate, newer environment due to library dependencies.*

---

### 3. Phase 2: Scientific Evaluation (Data Generation)

This phase generates the raw data required for the qualitative and quantitative analysis.

-   `evaluation.py`: The central evaluation engine. It performs the following:
    -   **Curates a Test Set:** Generates 50 prompts split into Normal Instructions, Verbosity Probes, and Hack Prompts.
    -   **Metric Calculation:** Computes KL Divergence (Drift), Perplexity (Forgetting), Reward Scores, and Constraint Compliance for every model.
    -   **Perturbation Test:** specifically tests the Reward Model's robustness by feeding it semantically identical but stylistically different inputs.
    -   **Output:** Saves raw data to `final_evaluation_results.csv` and `rm_perturbation_results.csv`.

---

### 4. Phase 3: Visualization & Reporting

These scripts transform the raw evaluation data into the figures and tables used in the report.

-   `generate_plots.py`: Reads the CSV outputs from the evaluation phase and generates the following artifacts:
    -   **Figure 3:** Box plots analyzing **Verbosity Bias** and distribution shape.
    -   **Figure 4:** Scatter plots visualizing the **Safety vs. Drift** trade-off.
    -   **Figure 5:** Dual bar charts quantifying **Constraint Compliance** rates and deviation magnitudes.
    -   **Figure 6:** Bar charts visualizing **Reward Model Overparameterization**.

---

### 5. Directories and Artifacts

-   `models/`: Stores the saved checkpoints for DPO, PPO, and the Reward Model.
-   `logs/`: Contains detailed training logs (loss curves, reward margins) for all runs.
-   `csv files/`: Stores the raw output data (`final_evaluation_results.csv`, `Table1_Data.csv`) generated by the evaluation script.
-   `figures/`: Contains the high-resolution `.png` plots generated by `generate_plots.py`.

## Installation & Usage

### 1. Main Environment (DPO, PPO, Evaluation)
Used for the majority of the tasks. Requires stable `trl` versions.
```bash
pip install torch transformers==4.36.2 trl==0.7.11 peft==0.7.1 datasets pandas seaborn matplotlib
```
### 2. GRPO Environment
GRPO requires a newer version of the TRL library. Create a separate environment for the script inside the `PA5_GRPO` folder.
```bash
cd PA5_GRPO
# Create/Activate venv
pip install torch transformers trl>=0.8.6 peft accelerate datasets 
```
